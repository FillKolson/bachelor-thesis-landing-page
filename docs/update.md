# Оновлення проєкту (release engineer / DevOps)

## Підготовка до оновлення

1. Проаналізувати зміни у релізі (git diff, changelog)
2. Створити backup (code + дані)
3. Перевірка залежностей та версій Node/npm

## Створення резервних копій

- Архів вихідного коду: `tar czf project-backup-$(date +%F).tar.gz /var/www/project`
- База даних (не у цьому репо, але у бекенді): `pg_dump`, `mysqldump` тощо

## Перевірка сумісності

- Запуск тестів: `npm run lint`, `npm run test` (якщо є)
- Перевірка Node.js, браузерів

## Планування часу простою

- Запланувати вікно з мінімальною активністю
- Повідомити користувачів

## Процес оновлення

1. Зупинити службу (якщо є): `systemctl stop nginx` або бекенд сервіс
2. Отримати новий код: `git fetch && git checkout release/x.y.z`
3. `npm ci` (або `npm install`)
4. `npm run build`
5. Копія `dist/` на production шлях
6. Оновлення конфігурації при потребі (`.env`, nginx)
7. Перезапуск nginx/сервісів:
   - `sudo systemctl restart nginx`

## Перевірка після оновлення

- Перевірити `curl -I` на URL
- Переконатися, що UI рендериться
- Перевірка логів: `sudo journalctl -u nginx -n 100`
- Перевірка в робочому браузері

## Процедура rollback

1. Якщо не працює — запустити `git checkout <попередній тег>` або відновити з backup
2. Копіювати перевірені `dist/`
3. Перезапустити сервіс
4. Повідомити команду

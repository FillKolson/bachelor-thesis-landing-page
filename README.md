# Інформаційна система тестування знань на базі чат-бота в месенджері Telegram

## Бакалаврська робота

### Загальна інформація

**Назва (англійською):** Information System for Knowledge Testing Based on a Telegram Chatbot

### Мета роботи

Розробити функціональну інформаційну систему тестування знань на базі чат-бота в месенджері Telegram, що демонструє володіння сучасними технологіями веб-розробки (React, Vite), системою контролю версій Git Flow та принципами створення доступних і SEO-оптимізованих інтерфейсів.

### Опис проєкту

Проєкт демонструє практичне застосування сучасних веб-технологій (React, Vite) та методології Git Flow при створенні адаптивного, SEO-оптимізованого лендінгу для представлення бакалаврської роботи.

**Ключові слова:** Telegram, чат-бот, тестування знань, інформаційна система, React, Vite, Git Flow, лендінг, SEO, доступність, адаптивність, веб-розробка, бакалаврська робота.

### Документування коду (JSDoc)

У проєкті використовується підхід **documentation-as-code**: документація пишеться прямо в коді у форматі **JSDoc** і може автоматично генеруватися у HTML.

#### Що документувати

- **Публічні інтерфейси**: експортовані компоненти/функції/класи.
- **Функції з побічними ефектами**: робота з `localStorage`, DOM, мережеві запити.
- **Нетривіальні частини логіки**: умови, алгоритми, важливі інваріанти.

#### Стандарт оформлення

- Для функцій/компонентів використовуйте блок `/** ... */` безпосередньо перед оголошенням.
- Обов'язково описуйте:
  - що робить сутність;
  - які side effects має;
  - `@param` для параметрів;
  - `@returns` для значення, що повертається;
  - за потреби `@typedef` для доменних типів.

#### Генерація документації

- Згенерувати документацію:
  - `npm run docs:generate`
- Перевірити якість JSDoc (eslint rules):
  - `npm run docs:lint`

Детальна інструкція: `docs/generate_docs.md`.

### Архітектурна схема проєкту

Проєкт є SPA на React з Vite, що статично сервуються у вебсервері.

- Веб-сервер: nginx / Vite Preview (dev) - тільки статичний хостинг.
- Application server: немає (frontend-only). API/бот, якщо додається, розгортається окремо.
- СУБД: немає у цьому репозиторії (frontend), може бути використано зовнішню базу даних для бота/серверу.
- Файлове сховище: статичні ресурси у `public/`.
- Кешування: браузерні заголовки, Service Worker можна додати додатково.
- Інші компоненти: CI (`.github/workflows`), Docker, docs, тестування через ESLint/Prettier.

> У разі необхідності серверну частину та СУБД слід додати як окремий сервіс (backend). Цей проект — фронтенд фронтенд-частини платформи.

### Для розробника: покрокова інструкція

1. Клонування репозиторію:
   - `git clone https://github.com/FillKolson/bachelor-thesis-landing-page.git`
   - `cd Project`

2. Необхідні залежності:
   - Node.js (LTS >= 18)
   - npm (>= 9) або yarn
   - Git

3. Налаштування середовища:
   - Встановити Node.js та npm (або nvm)
   - Опціонально: VS Code + розширення ESLint, Prettier

4. Встановлення залежностей:
   - `npm install`

5. Налаштування БД (не застосовується для frontend-only). Якщо розгортаєте бекенд:
   - створити базу даних (PostgreSQL/MySQL/MongoDB) за документацією бекенду
   - додати `.env` з `DATABASE_URL` і т.д.

6. Запуск у dev-режимі:
   - `npm run dev`
   - Відкрити `http://localhost:5173`

7. Базові команди:
   - `npm run build` — збірка на продакшн
   - `npm run preview` — локальний перегляд збірки
   - `npm run lint` — перевірка ESLint
   - `npm run docs:generate` — згенерувати документацію (якщо налаштовано)

8. Перевірка:
   - Працює на `http://localhost:5173`
   - Перемикання теми
   - Адаптивність на мобільних пристроях
